# Abstract

## Title
**Q-Commerce Price Intelligence: A Reusable, Schema-Driven Data and Machine Learning Pipeline**

## Problem statement

The Quick-Commerce (Q-Commerce) sector — characterised by ten-minute hyper-local delivery of groceries, electronics, and household goods — has emerged as one of the fastest-growing segments of digital retail. Despite the volume of catalogue and pricing data flowing through these platforms every minute, structured longitudinal datasets are rarely available to researchers or analysts, and the platforms themselves expose only consumer-facing interfaces protected by aggressive anti-automation defences.

This project addresses the gap by building a complete data science pipeline that **(i)** acquires real product catalogue data from a Q-Commerce delivery platform, **(ii)** cleans and enriches it through a reusable, schema-driven processing layer, **(iii)** trains and evaluates three machine-learning models that answer practical pricing-intelligence questions, and **(iv)** surfaces the resulting insights through an interactive dashboard.

## Methodology

### Data acquisition
An asynchronous Python scraper using `curl_cffi` for TLS-fingerprint impersonation, `playwright` for dynamic authentication-token capture, and `asyncio` for high-concurrency request handling. Adaptive backoff handles HTTP 429 rate-limiting; self-healing session refresh handles token expiry. Data is persisted to a `DuckDB` analytical store with an append-only `price_history` schema.

### Data preparation
A modular cleaning pipeline performs schema validation, constant-column elimination, product-level deduplication, multi-pack unit normalization, rare-unit bucketing, and missing-value imputation. Feature engineering derives discount percentage, price-per-unit, log-transformed price, multi-pack and out-of-stock flags, and a keyword-to-category reverse mapping.

### Modelling
Three machine-learning models are trained:

1. **Random Forest Regressor** for product-price prediction from attributes (MRP, brand, category, unit characteristics, rating, inventory). Achieves R² = 0.825 with mean absolute error of approximately ₹40 on a held-out test set.

2. **Random Forest Classifier** for high-discount detection (≥15% off MRP). Achieves 85.9% accuracy, F1 = 0.88, and ROC AUC = 0.94.

3. **K-Means clustering** with PCA-based 2-dimensional visualization for unsupervised product segmentation. Yields four interpretable clusters spanning mass-market, mid-tier, premium, and electronics-outlier segments.

### Visualization
Eight exploratory data analysis charts and six model-evaluation charts are auto-generated by the pipeline. A `Streamlit` dashboard with six tabs presents the EDA, model metrics, a live inference page for the price predictor, discount insights, cluster browser, and pipeline diagnostics.

## Key contribution

The pipeline is **platform-agnostic within its schema**. Every cleaning and feature-engineering rule is derived from observed data patterns documented in a separate specification file (`OBSERVATIONS.md`). A new dataset from another Q-Commerce platform with the same column structure can be processed end-to-end by changing a single command-line argument; no code modifications are required.

## Scope and limitations

The current dataset is a single-day snapshot of approximately 14,000 product records spanning 27 categories. Time-series forecasting — using libraries such as `Prophet` or Random Forests with lag features — was deliberately scoped out of this iteration because forecasting requires longitudinal data accumulated over weeks. The architecture (timestamped storage, schema-aware pipeline) is designed to absorb daily snapshots without modification, enabling a future forecasting layer to be added incrementally.

## Tools and libraries

`Python`, `asyncio`, `curl_cffi`, `playwright`, `polars`, `pandas`, `DuckDB`, `scikit-learn`, `matplotlib`, `seaborn`, `plotly`, `streamlit`, `joblib`.

## Conclusion

This project demonstrates that a small team can construct, in a single iteration, a production-style data and ML pipeline that spans acquisition through dashboard delivery — and that thoughtful documentation of data patterns turns a one-off project into reusable infrastructure for the broader Q-Commerce analytics problem.
